# Compact Handoff

Creates compact-safe handoff files under `memory/session_handoffs/` when a session reaches context pressure or compacts.

- `message:preprocessed`: if the persisted session is at high context pressure, saves an early handoff before compaction is required. Per-session serialization closes concurrent first-crossing races. A five-minute hard floor prevents per-turn writes. After the floor, soft-to-high can refresh; a 10K delta refresh is high-to-high only; and the normal twenty-minute interval never overrides high-to-soft suppression. A no-write soft observation is retained so a later rise to high remains detectable.
- `session:compact:before`: saves a pre-compact handoff with recent user/assistant turns and session metadata. Transcript ownership comes from the bounded authoritative agent `sessions.json`; every authority-root ancestor is owner-matching, non-group/world-writable, and non-symlinked. A direct event path is usable only when its session ID and pathname exactly match the conventional regular file beneath that agent's sessions directory. Conventional validation is bound to the opened transcript's device/inode identity, and bounded store/transcript reads verify the opened identity again afterward, so replacement/append/truncation races fail closed.
- `session:compact:after`: updates the handoff with post-compact stats and a bounded audit of the newest persisted native compaction summary. It reads at most the newest 2 MiB of the authoritative session JSONL, retains a complete first row when the read begins exactly on a JSONL boundary, and records only availability, verdict, fixed reason codes, and summary length; it does not copy or rewrite the native summary. The observed length remains preserved through later index mutations even when the summary exceeds the 16,000-character quality cap.
- `agent:bootstrap`: injects only the matching `memory/session_handoffs/session_<sessionStorageId>.MEMORY.md` into bootstrap context when present. The current file and lifecycle state are bounded regular-file reads and final symlinks fail closed. Unsafe or truncated session keys receive a deterministic SHA-256 suffix so two raw keys cannot share storage. Because OpenClaw 6.11/7.1 expose no generation-correlated outbound delivery event, the hook conservatively attempts each generation once, persists `consumed:false` / `injected-once-unconfirmed`, expires it after 24 hours, and never claims confirmed consumption. Status/attempt combinations are strict (`injected-once-unconfirmed` = one; `expired` = zero); inconsistent or malformed lifecycle state fails the current attempt closed and becomes redacted quarantine metadata. The approved availability-first policy permits a separate clean retry and accepts the resulting residual duplicate-offer risk. Project recovery remains independent.

When `memory/project_states/registry.json` maps the current `sessionKey` to a project, the hook also adds a compact project recovery pointer. This pointer is deterministic and only reads:

- `memory/project_states/<project>/ACTIVE_TASK_STATE.json`
- `memory/project_states/<project>/PROJECT_GATES.json`

Unregistered sessions behave exactly like the baseline session-only handoff path.

The hook is intentionally deterministic and local-only: it does not call external APIs or another LLM from inside the gateway hook path. Archives, current handoffs, state, and index use temp-file + sync + atomic rename. Process-local queues plus owner-only exclusive filesystem locks serialize per-session and shared-index transactions across independent handler instances using one workspace. Lock waits are bounded. Stale recovery requires bounded/no-follow metadata naming an owner PID that no longer exists. A fixed owner-only recovery marker elects one reaper and gates new acquisition before and after lock creation; unknown or live owners are not stolen based on age alone. If that reaper dies, its marker is preserved and attempts fail closed pending verified manual removal. An owner-only, no-follow, exclusive pending-current marker spans current/index commit; a pre-existing unresolved marker blocks later writes and bootstrap without being overwritten, and identity-guarded cleanup cannot remove another transaction's marker. Ordinary index failure restores the previous current and removes the uncommitted archive, while rollback failure retains the marker/archive and makes bootstrap fail closed. Lifecycle state is schema-allowlisted and capped at 32 KiB; generation identities accept only UUID or `legacy-<32 hex>` forms, and status/attempt combinations are validated together. Malformed, oversized, inconsistent, or present-but-invalid state is replaced by bounded redacted quarantine metadata and fails that bootstrap attempt closed; the availability-first contract allows the next clean attempt to recover. Corrupt regular artifacts are pruned to three files and seven days, including routine successful commits; only exact `timestamp-pid-UUID` quarantine suffixes are eligible, so neighboring primary state files are never retention targets. Non-regular artifacts are ignored safely, while permission and other I/O failures abort without quarantine. Authorization/Proxy-Authorization credentials of every scheme, including quoted text keys, `:`/`=` assignments, repeated/mixed LF or CRLF folds after quoted or adjacent segments, shell-wrapped multiline values, adjacent shell quote segments, and unquoted escaped shell words, are redacted. Any LF/CRLF shell line-splice at or after a decoded credential-header assignment fails the bounded evidence item safe as a whole, including residual-backslash quote-parity cases; the splice scan uses linear traversal and constant offset state through the tail bound. Complementary near-bound stress fixtures place every assignment before every splice and every splice strictly before every assignment, exercising both outcomes without a nested header-by-splice search. Dynamic `$()`, `${}`, `<()`, and `>()` introducers split across one or more shell line-splices also fail safe, as do expansions adjacent to a header, inside its enclosing quote, or inside an adjacent quoted segment; redaction continues through the bounded evidence remainder before nested shell quotes are interpreted. Complete JSON values are parsed before dispatch: decoded nested Authorization/Proxy-Authorization/Cookie/Set-Cookie keys in objects/arrays are replaced, non-sensitive fields within the 64-level traversal bound remain, deeper subtrees fail safe, and recursively encoded JSON-string layers are decoded and scanned before valid compact JSON is serialized. Ordinary strings and terminal JSON-looking primitive strings retain lexical content while using the text scanner. Quoted shell keys do not qualify as structured fields by quoting alone. Only assistant provenance can assert deterministic completion/blocking status. The exact preloaded session handoff is removed before lifecycle I/O, and project recovery remains independent. Because collision-resistant storage IDs cannot contain `@`, archive ownership accepts either an exact legacy storage ID or an exact reserved `@<uuid>` suffix grammar, never a delimiter prefix. Retention pins the archive referenced by the committed index, keeps at most five snapshots per exact session/phase, and removes other archives older than thirty days without targeting a prefix-neighbor or current/state/index file. Index reads are capped at 512 KiB, no-follow, post-read identity checked, and schema-sanitized before mutation.
